# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SELENE is an open, self-paced learning platform for AI/ML and related topics, delivered as a large collection of teaching Jupyter notebooks (~76 originals) backed by a shared Python helper library under `notebooks/src/`. There is no application to build, no test suite, and no `requirements.txt` — the "product" is the notebooks plus their supporting code. Code is MIT; text/figures are CC BY 4.0.

## Critical convention: run everything from `notebooks/`

The `notebooks/` directory is the working root for all execution. Notebooks and helper code assume the current working directory is `notebooks/`:

- Imports use the package form `from src.utils.libimports.<topic> import *`, which only resolves with `notebooks/` on `sys.path` (i.e. CWD = `notebooks/`).
- `src/utils/data/files.py` loads config as `../config.yaml` (repo root) and downloads into `data/datasets/` — both relative to `notebooks/`.

Start Jupyter from there:

```bash
cd notebooks && jupyter lab        # or: jupyter notebook
```

Execute a single notebook headlessly (useful for verifying changes):

```bash
cd notebooks && jupyter nbconvert --to notebook --execute --inplace <name>.ipynb
```

Dependencies live in `requirements.txt` (repo root), generated from the imports across all notebooks and `src/`. They are unpinned by design — imports also sit at the top of each notebook so any missing package surfaces immediately. This repo uses a **conda virtual env named `selene`**:

```bash
conda create -n selene python=3.11 -y
conda activate selene
pip install -r requirements.txt
```

`requirements.txt` excludes the standard library and the local `src` package. `faiss-cpu` is listed by default; swap to `faiss-gpu` for CUDA. When adding a new third-party import to a notebook or `src/`, add it to `requirements.txt` too.

## Architecture

**`notebooks/*.ipynb`** — the main interactive teaching notebooks, one self-contained topic each. They deliberately keep cells clean by delegating boilerplate to `src/` via a three-line import pattern at the top:

```python
from src.utils.libimports.<topic> import *   # bundled third-party imports for this topic
from src.utils.plotting.<topic>   import *   # matplotlib/seaborn figure helpers
from src.utils.data.files          import *  # download_dataset / download_file / decompress_file
```

**`notebooks/src/`** — shared helper library imported by the notebooks:
- `models/` — pedagogical / from-scratch model implementations (`linear/`, `trees/`, `ngram/`, `neural/transformer.py`) using numpy/torch.
- `text/` — `preprocessing/` (normalizing, stemming, tokenizing) and `vectorizing/` (vocab).
- `utils/`:
  - `libimports/` — one module per topic that re-exports the third-party libraries that topic's notebook needs. This is why notebooks can `import *` a single module instead of listing imports.
  - `plotting/` — one module per topic with the figure-generating functions used in that notebook.
  - `data/files.py` — dataset/model download + decompress helpers; reads base URLs from `config.yaml`.
  - `compute/gpu.py`, `helpers/`, `preprocessing/`, `sampling/`.

**`notebooks/standalone/*_standalone.ipynb`** — auto-generated, Colab-ready copies of the originals with all `src/` helper code and config inlined so they run with no repo dependencies. **Do not hand-edit these.** They are regenerated from the originals by a custom conversion script (not in this repo); edit the original notebook in `notebooks/` instead.

**`notebooks/data/`** — default download target. Datasets and pretrained models are **not** in the repo (too large); they are fetched at runtime by `download_dataset()` from the URLs in `config.yaml` and cached here (gitignored). Downloads are skipped if the file already exists unless `overwrite=True`.

**`config.yaml`** (repo root) — base URLs for downloading datasets and models. If runtime downloads fail, check these URLs against the upstream copy.

## When making changes

- Adding/using a new third-party import in a notebook: add it to the topic's `src/utils/libimports/<topic>.py` rather than importing directly in a cell, to match the existing pattern.
- Plotting code belongs in `src/utils/plotting/<topic>.py`, not inline in the notebook.
- After editing an original notebook, remember its `standalone/` counterpart is stale until regenerated by the (external) conversion script.
